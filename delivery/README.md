# PastroVoice Layer 4: Delivery

This module prepares Layer 3 broadcasts for community radio and demonstrates a
feature-phone IVR menu in a browser. It lives at the root of the Pastrovoice Git
repository, alongside `backend/`, `frontend/`, `pipeline/`, and the Layer 3
Python package in `pastrovoice/`. It is separate from that nested Layer 3 package.

## What is included

- `app.py`: FastAPI API for the broadcast catalog, audio and cue-sheet access,
  downloadable radio ZIP packs, and IVR menu/key presses.
- `catalog.py`: discovers only complete Layer 3 MP3 and JSON cue-sheet pairs.
- `packs.py`: builds a station ZIP containing the audio, cue sheet, manifest
  (with SHA-256 checksums), and station hand-off notes.
- `static/`: standalone browser UI with a pack list and simulated phone keypad.
- `__main__.py`: local development entry point.

## How it connects to the other layers

Layer 1 supplies climate and observation data. Layer 2 stores and derives
ward-level indicators and advisory facts. Layer 3 maps those facts into a
two-speaker script and MP3. Layer 4 reads the paired outputs from the repository
`output/` folder and exposes the same artifacts as station ZIPs and browser IVR
playback. The IVR simulation exercises the language and ward selection flow; it
does not place or receive a real telephone call.

Layer 5 can use the HTTP API from its separate UI module. The catalog returns
audio, cue-sheet, and ZIP URLs, so the cockpit can embed a player, link to a
cue sheet, or provide a pack download without importing Layer 4 internals. The
existing `frontend/index.html` dashboard now includes a small “Community
broadcast studio” panel. It fetches the catalog, previews each MP3, and links to
the cue sheet and ZIP. It defaults to `http://127.0.0.1:8010`; the address can be
changed in the panel and is remembered in the browser. The Layer 4 browser page
is a standalone keypad demo and does not replace the Layer 5 command center.

The project already has FastAPI, Uvicorn, and Pydantic declared in
`lastmile/pyproject.toml`. Layer 4 does not require Streamlit or a new runtime
dependency. The existing Africa's Talking messaging integration handles SMS;
live voice/IVR is outside this module and is not claimed as implemented.

## Run locally

From the Pastrovoice Git repository root:

```powershell
python -m pip install -e .\lastmile
python -m delivery
```

Open `http://127.0.0.1:8010`. The API schema is at `http://127.0.0.1:8010/docs`.
The default artifact directory is the repository's `output/` folder. To use a
different folder, set `PASTROVOICE_OUTPUT_DIR` before starting the server. The
Layer 5 dashboard's local origins on port 8000 are allowed by default; set
`PASTROVOICE_DELIVERY_CORS_ORIGINS` to a comma-separated list if the dashboard
runs at another origin.

Generate Layer 3 artifacts into `output/` first, for example:

```powershell
python -m pastrovoice.engine --ward "Laisamis" --lang sw --out output
python -m pastrovoice.engine --ward "Laisamis" --lang en --out output
```

Layer 4 lists only a matching non-empty `*_advisory.mp3` and `*_script.json`
pair, where the JSON contains a ward and dialogue. Existing sample artifacts in
`output/` can be used for an offline demo.

## API used by Layer 5

- `GET /health` — service status and number of available broadcasts.
- `GET /api/catalog` — ward/language entries with audio, cue-sheet, and ZIP URLs.
- `GET /api/audio/{ward_code}/{language}` — stream an MP3.
- `GET /api/cue-sheet/{ward_code}/{language}` — download the Layer 3 JSON cue sheet.
- `GET /api/radio-packs/{ward_code}/{language}.zip` — download a station pack.
- `GET /ivr/{ward_code}/menu` — initial menu for a ward, if needed by a client.
- `POST /ivr/keypress` — advance a stateless IVR simulation using node, language,
  ward code, and one keypad digit.

`GET /api/catalog` is the simplest integration point for Layer 5. The server
serves its page at `/`; static assets are under `/delivery-assets/`.
For local integration, run Django and Layer 4 on the same machine, then use the
“Load broadcasts” control in the dashboard panel. Layer 5 only reads the
catalog and links to the Layer 4 media and pack routes; it does not duplicate
Layer 3 generation or delivery logic.

## Scope and limitations

The browser IVR is a demonstration of the caller flow and plays MP3 files through
the browser. Africa's Talking live voice calling is not implemented here; the
repository's existing provider integration is for SMS. Audio artifacts must
already have been generated by Layer 3. If a ward/language pair is missing or
incomplete, the catalog omits it and the API returns a clear not-found response.
